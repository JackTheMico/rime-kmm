# 空明码一击字（单键一击与空格并击）现状调研与优化方案报告

> **调研背景**：空明码用户反馈在日常录入中，部分“一击字”（含单手直接击发的一简字、单手大写并击字及空格并击字）并非现代汉语的高频常用字，导致黄金键位被低频字占据，而真正超高频的汉字却需多次击键或全码输入。
> 本报告基于**权威一手资料**（空明码原版设计文档、RIME 码表源码）与**国家语委现代汉语单字字频权威数据库**（笪骏/Jun Da 语料库，2.58 亿字规模），对空明码全部 208 个一击字槽位进行了全量字频统计、分布排查与归因分析，并提供两套可直接落地的优化方案。

## 1. 核心定义与数据依据（一手权威来源）

### 1.1 一击字的定义与范围
在《空明码说明文档20230726.doc》第 1.1 节「一简上屏字」与第 2.3 节「拇指并击」中，原作者对一击字的定义如下：
> “一简上屏字是指打一个码元就上屏的字，即一击上屏字；将系统切换到中文录入状态后只用左手录入码元 a 即可打出‘啊’字，只用右手录入码元 n 即可打出‘你’。请熟练掌握下面的一简字列表（括号里面的字表示与空格并击输出的字，比如只打 a，输出‘啊’，a+空格 输出‘唉’）……”

在当前 RIME 码表实现（[`kongmingmas.dict.yaml`](file:///home/jackwy/Nextcloud/kmrime/kongmingmas.dict.yaml) 与 [`kongmingmas.schema.yaml`](file:///home/jackwy/Nextcloud/kmrime/kongmingmas.schema.yaml)）中，一击字体系由 **26 个英文字母 × 8 种击键状态 = 208 个槽位** 构成（其中 4 个右手槽位固定映射为中文标点 `；，。、`，实际汉字槽位 204 个）：

| 击键形态 | 编码特征 | 动作描述 | 槽位数量 |
| :--- | :--- | :--- | :--- |
| **左手小写基础** | `x=` | 左手单键或单手跨键小写码元击发 | 26 |
| **右手小写基础** | `=x` | 右手单键或单手跨键小写码元击发（含标点） | 26 |
| **左手大写码元** | `X=` | 左手单手两键并击输出大写码元 | 26 |
| **右手大写码元** | `=X` | 右手单手两键并击输出大写码元 | 26 |
| **左手小写空格并击** | `x_=` | 左手小写码元 + 拇指空格同时并击 | 26 |
| **右手小写空格并击** | `=_x` | 右手小写码元 + 拇指空格同时并击 | 26 |
| **左手大写空格并击** | `X_=` | 左手大写码元 + 拇指空格同时并击 | 26 |
| **右手大写空格并击** | `=_X` | 右手大写码元 + 拇指空格同时并击 | 26 |
| **总计** | — | — | **208 槽位** |

### 1.2 物理按键成本分级（Tier 0 ~ Tier 3）
在双手键盘并击录入中，虽然上述 208 个字均属于“一击上屏”（单次击键动作），但其**生理负荷与按键成本存在显著阶梯**：
- **T0（纯单物理键击发，成本最低）**：左右手各 15 个物理字母键（左手 `q w e r t / a s d f g / z x c v b`，右手对应映射）。无需任何并击，单指瞬间直下，速度最快。
- **T1（单手跨键小写并击，次低）**：输出其余 11 个小写字母（如左手 `w+f -> h`，`d+f -> j`，`s+d -> k` 等）。
- **T2（单手大写两键并击，中等）**：单手两键组合触发大写码元（如 `a+v -> A`，`q+w -> B`）。
- **T3（单手键 + 空格并击，较高）**：需加入拇指并击动作。

### 1.3 字频参照系
字频数据来自国家语委规范标准及 **Jun Da（笪骏，MTSU）现代汉语单字字频权威数据库**（基于 193,504,018 现代汉字平衡语料，收录 9,933 个规范汉字）。

## 2. 现状调研与核心痛点诊断

### 2.3 超高频核心汉字严重缺失（空明码最大的效率漏洞）
对比发现，现代汉语中最具统治力的高频字，竟大量被排除在一击字之外：
- **现代汉语 TOP 20 中有 5 个字缺席**：
  - `中`（#14，频次 1,104,541）
  - `来`（#15，频次 1,079,469）
  - `上`（#16，频次 1,069,575）

  - `国`（#20，频次 985,350）
- **现代汉语 TOP 50 中有 27 个字缺席（缺失率高达 54%）**！
  - 缺失字：`到` (#22)、`说` (#24)、`时` (#25)、`出` (#28)、`会` (#29)、`也` (#31)、`对` (#33)、`生` (#34)、`能` (#35)、`子` (#37)、`那` (#38)、`于` (#40)、`着` (#41)、`下` (#42)、`自` (#43)、`之` (#44)、`年` (#45)、`过` (#46)、`发` (#47)、`后` (#48)、`作` (#49)、`里` (#50)。

> 而录入 500 次都不到的 `孺`、`敖`、`噩`、`啃`、`屁`，却可以一击瞬间上屏！

### 2.4 同字重复与位次冗余
除了低频问题，当前码表中还存在 6 组完全相同的单字在不同槽位重复出现，直接白白损耗了 6 个席位：
1. **耳**：重复出现在 `E=`（左大写）与 `_e`（右空格）
2. **华**：重复出现在 `=H`（右大写）与 `H_=`（左空格大写）
3. **易**：重复出现在 `_I`（右空格大写）与 `V_=`（左空格大写）
4. **尽**：重复出现在 `=J`（右大写）与 `u_=`（左空格小写）
5. **令**：重复出现在 `=L`（右大写）与 `l_=`（左空格小写）
6. **首**：重复出现在 `=S`（右大写）与 `_O`（右空格大写）

### 2.5 原作者编排逻辑的根本归因
为什么会出现如此严重的失衡？
通过逆向分析可知：原作者在设计 208 个一击字时，**严格采用了“拼音声母首字母对齐（Sound Initial Mnemonic）”的心智记忆模型**：
1. 原作者希望用户按键时“以音联想”：按 `K` 对应 `k` 声母字；按 `P` 对应 `p` 声母字；按 `E` 对应 `e` 开头的字。
2. 每一个字母强行安排了 8 个槽位（左右小写、左右大写、左右空格小写、左右空格大写）。
3. 致命矛盾在于：**汉语拼音各声母的常用字资源分布极度不均**！
   - 以 `d, z, s, j, y, x, g, h` 为声母的汉字多如牛毛，超高频字挤破头（导致 `大`、`中`、`时`、`上`、`国`、`会` 被挤出）；
   - 而以 `e, o, p, k, r, f` 为声母的汉字资源极其匮乏：
     - `e` 开头常用字只有 `而`、`二`、`儿`，为了凑齐 8 个位置，硬塞进 `耳`（重复2次）、`饿`、`峨`、`噩`；
     - `p` 开头硬塞进 `屁`、`婆`、`聘`、`迫`、`飘`、`拍`；
     - `o` 开头本就无字，只能全是叹词 `哦/噢/哟/偶`；
     - `k` 开头硬塞进 `啃/矿/壳`；
     - `f` 开头硬塞进 `沸/疯/凤/冯`。

## 4. 优化方案一：声母对齐·高频同位替换方案（推荐首选）

### 4.1 方案定位
- **核心原则**：**绝对不破坏拼音声母联想体系**！每个字母键位依然严格对应其拼音声母汉字。
- **改动手段**：
  1. 彻底淘汰原键位中 Rank > 500 的生僻字、粗俗字（`屁`、`噩`、`敖`、`啃`、`孺` 等）以及重复字；
  2. 在**相同声母**的候选池中，遴选**字频最高且尚未被分配一击码的核心常用字**予以替换。
- **学习成本**：极低。打字习惯平滑升级，原有按音找键的心智模型 100% 保持。

## 5. 优化方案二：极致速度·Top 100 全覆盖重构方案（进阶专业向）

### 5.1 方案定位
方案一虽然实现了 43.55% 的覆盖率且保留了声母联想，但受限于部分字母天然缺乏高频字（如 E/O/P/U/V），依然有部分 Top 100 汉字未能进入一击。
**方案二的目标是达到输入法的理论速度天花板**：
- **原则**：完全以**击键人体工学**与**真实字频**为最高纲领；
- **T0 物理纯单键（30个位置）**：必须被现代汉语 **Top 1~30 的绝对高频字** 完全占满（如 `的、一、是、不、了、在、人、有、我、他、这、个、们、中、来、上、大、为、和、国、地、到、以、说、时、要、就、出、会、可`）；
- **大写及空格并击（T1~T3）**：覆盖全部剩余的 Top 31~100 汉字；
- **效果**：现代汉语日常输入的单字击键，**每两下击键就有一次是一击直接上屏**，语料覆盖率直接飙升至 **57.97%**。
