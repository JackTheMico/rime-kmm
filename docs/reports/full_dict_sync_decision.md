# 全量版 kongmingma 同步决策（票 06）

> Effort: `km-code-length-0.6`　决策日期: 2026-11-16　决策人: 维护者（本轮实施代理代记，见下"生效条件"）

## 决策

**不同步（本轮）**。本轮码长优化的所有成果仅保留在隔离实验方案 `kongmingmas_exp{,_t}`，
不推广到 300 万全量版 `kongmingma.dict.yaml`，也不写回生产简版 `kongmingmas`。

## 理由

1. **成果本身尚在实验方案**：票 04 的 603 个空槽挂词、票 05 的裁决都落在 `kongmingmas_exp`，
   活动方案仍是 `kongmingmas`，部署器写死 `MAIN_SCHEMA=kongmingmas`，用户实际输入法未切换。
   实验方案要不要转正尚未拍板；在全量版上同步一个未转正的实验成果为时过早。
2. **0.6 目标已裁决为不可达**（见 `docs/reports/code_length_06_verdict.md`）：本轮稳定点是 0.7，
   且只在隔离副本上验证过。全量版同步没有额外收益可兑现。
3. **全量版简码早已分叉且未维护**：项目记忆与文件时间戳一致显示——
   `kongmingma.dict.yaml` 自 2026-11-08 起未再改动（51MB，300 万词条），
   而 11-08 之后所有简码优化（数字族开槽 / 回收 / 死码 / 一词一码 / 码位首候选回补 / 本轮扩容）
   都只作用于 `kongmingmas*`。同步本轮 603 条只是把已经存在的长期分叉再拉开一点，
   单独追平历史欠账是另一轮、工作量独立的任务。
4. **成本与风险不对称**：单文件 51MB（近 GitHub 100MB 单文件上限一半），简繁双份写库 + 备份
   + 全量重编译验证；而收益是零（0.6 不可达、实验未转正）。不值得。

## 长期分叉事实（如实记录）

- **简版 `kongmingmas`（160 万，26MB）与全量版 `kongmingma`（300 万，51MB）的简码自 2026-11-08 起长期分叉**。
  全量版停留在旧简码体系；简版持续演进。两版的同词简码可能不同，用户跨版迁移需重新适应。
- 本轮 `kongmingmas_exp` 是简版的第三次分叉（实验副本），三者简码互不相同。
- 该分叉状态在有人明确决定"追平全量版"之前保持不变，不会自动收敛。
