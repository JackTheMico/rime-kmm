# 票 01 — 一击码面的物理容量与扩容上限

## Question

在不破坏现有并击规则的前提下，**一击上屏码位的物理上限到底是多少**？具体回答：

1. `km_chord_model.py` 枚举的 9111 个一击可达码中，有多少能做成「零延伸 + 唯一候选」的自动上屏码？当前 1396 个一击上屏码距这个上限还有多远？
2. 已开的族（纯字母 / `0` / `7/8/9` / 符号前后缀 / 空格并击）各自剩余多少**干净且符合左右手约束**的槽位？哪些族已饱和、哪些还有空间？
3. 按项目铁律复核：`X~` 数字大写族是否仍必须永不外借？`1`–`6` 是否仍不可便宜使用？有没有新族可开（如双符号、三键并击的可达码）？

这是后面所有「改派/扩容/一词一码」决策的天花板。用权威工具算，不要肉眼估计。

## Answer

一击可达码面硬上限 **9111**，当前自动上屏仅 **1377**（15.1%）；干净可直接用的空槽 **5086**，被延伸码占用 2459、多候选 189。1396 vs 1377 的 19 个差额是含 1–6 / 数字组合的死码。铁律复核通过：`X~` 数字大写族保住、`1`–`6` 仍不可用。最现实扩容方向是符号前缀族（`_`132/`.`112/`*`110/`,`109…）与 `0/7/8/9` 数字前缀族，另有双符号码 179、大写+符号 390 等新族。结论：码面空间不是瓶颈（可扩至 6652 而不破坏长词），零和分配才是。详见 `research/one-strike-capacity.md`。
