# 票 04 — 验收协议：理论与实测如何定义与测量

Type: grilling
Status: resolved
Blocked by:

## Question

终点要求「理论可达 + 实测逼近」。但两者都没定义清楚就无法判断达标。需与用户一次一问地拍板：

1. **理论码长**：按哪份词表/语料算？口径是否就是跟打器的「理想码长」（程序按码表算出的最短值）？打词率 `p` 是假设值还是从词表推？
2. **实测码长**：是否就是 52dazi「码长」定义（总键数/总字数）换算到并击口径？用什么文本测（固定赛文 / `essay.txt` / 日常随机）？谁打、打多少字算数？
3. **达标线**：0.6–0.7 是理论值、实测值，还是两者各自一条线？允许误差区间？
4. 是否把「打词率」「选重率」列为配套约束指标（避免靠极端打词率凑出低码长）？

这是后续所有技术票的验收尺子。

## Answer

用户拍板（2026-11-16，分两轮）——

**验收标尺（两条独立线）**
- 理论码长 ≤ **0.7** 击/字（0.6 作为 stretch goal，非硬线）。
- 实测码长 ≤ **0.8** 击/字。
- 两者独立判定，不以理论达标替代实测，也不以实测偶达掩盖理论未达标。

**计击口径（严格）**
- 预测/联想上屏的字计入击数；需空格确认的「有延伸码」计入击数。
- 目的：杜绝靠新机制把账面码长做低。此口径下顶功/联想对码长几乎无净贡献（呼应票 03 的风险提示）。

**理论码长口径**
- 采用**跟打器「理想码长」**：程序按码表计算每个字词的最短击数，打词率 `p` 从固定高频词表推算。
- 可复现、与用户习惯无关，对应 52dazi 榜单的「理论」列。

**实测码长测法**
- 采用**日常随机文本**，不固定语料、不设标准样本，记录真实打字表现。
- 代价（如实记录）：不可复现、样本间难横向对齐；因此必须依靠下述配套约束夹逼，否则单条成绩无法判定达标。

**配套约束（双约束）**
- 打词率 `p` 与选重率同时列为验收指标，须同时达标才算通过。
- 目的：防止靠极端打词率（只打超短词）凑低码长，也防止靠无限扩大候选堆覆盖。

**对下游票的约束**
- 票 05 让槽方案必须在 p 与选重率双约束下评估，不得只看码长。
- 票 06 打词率路径须给出真实文本下的 p 测量法，而非仅模型推演。
- 验收脚本须同时输出四个数：理论码长 / 实测码长 / p / 选重率，缺一不判达标。
