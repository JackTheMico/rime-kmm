# 票 02 — 高频词的一击覆盖率缺口（研究代理「词覆盖」）

> 分析日期：2026-11-16　分析脚本：`.scratch/km-code-length-0.6/research/word_coverage_analysis.py`（只读，未改词库）
> 权威口径：击中数由 `tools/km_chord_model.py` 判定（一次并击=左右各一码元=1击）；词频取 Rime 官方 `essay.txt`（经 opencc 转简）。
> 本文件为新增报告，词库与现有文件均未修改。

## ① 结论先行

1. **当前一词一击覆盖率远不足以撑起 p≥74%/87%。** 二字词一击覆盖率（按词条数）前 1000 / 5000 / 2 万高频词分别为 **71.0% / 32.9% / 11.1%**；若按语料词频加权（真正决定打词率的口径）为 **84.4% / 61.9% / 48.9%**。越往高频尾部，缺口越大——二字词平均码元数从前 1000 的 2.58 涨到前 2 万的 3.77，远超外部研究「词均码元数 ≤2」的硬前提（§③）。
2. **要「撑住」p≥74%/87% 这两个门槛，覆盖率需要接近满格。** 在 c1=1.269、L=2、未覆盖词退化为 2 击的框架 A 下：锁定 p=74% 要 K=0.7，覆盖率需 **≥99.98%**；锁定 p=87% 要 K=0.6，需 **≥99.99%**（§③.2）。换言之，52dazi 报告给出的 74%/87% 门槛，隐含「词几乎全部一击」这一前提；当前 71%（词数）/84.4%（词频）的二字词覆盖率**达不到**。
3. **换一个更宽松的自洽口径，门槛降到 83%/92%，仍高于现状。** 若打词率受覆盖率约束（p≤q，即只有能一击的词才会被打），则解析解得 K=0.7 需覆盖率 ≥**83.1%**、K=0.6 需 ≥**91.9%**（§③.3）。当前前 1000 二字词按词频加权 84.4% 刚过 K=0.7 线、但离 K=0.6 仍差 7.5 个百分点；前 5000/2 万则彻底够不着。
4. **一击槽位是零和的，给词扩容必然稀释单字一击率。** 一击上屏码共 1377 个（单字 529 / 词 781 / 其他 67）。每把 100 个槽从单字转给词 = 吃掉 18.9% 的单字一击地盘：若优先转榜单外低频槽，前 1500 字一击率仅掉 **1.7 pp**（30.3%→28.6%）；若均匀或优先转高频槽，掉 **5.7–6.7 pp**（§④）。
5. **核心矛盾**：缺的不是「多塞几个词进一击层」，而是「一击槽总量固定（约 1377） vs 高频二字词数以万计」。即便把全部 781 个词槽都给二字词，也只能覆盖前 1000 高频二字词的一半左右。覆盖率与单字一击率不可兼得，必须二选一或扩大一击码空间（改 algebra / 增码元），后者超出本票范围。

## ③ 缺口推导

沿用 `docs/reports/52dazi_code_length_research.md` §4 的模型（c1=单字平均击数=1.269，L=词长=2，`cw=⌈m/2⌉`=词平均击数），并引入覆盖率 q。设二字词中比例 q 能一击（cw=1）、其余 1−q 退化为两击（cw=2），则词平均击数 `cw = 2 − q`，代入：

```
K = (1 − p)·c1 + p·(2 − q)/L = c1 − p·(c1 − (2−q)/2)        （L=2）
```

### ③.1 现状代入：当前覆盖率对应的打词率门槛

| 二字词范围 | 覆盖率 q（词数 / 词频） | K=0.7 所需 p | K=0.6 所需 p |
| :--- | :--- | ---: | ---: |
| 前 1000 | 71.0% / 84.4% | 0.912 / **0.823** | 1.072(无解) / 0.968 |
| 前 5000 | 32.9% / 61.9% | 1.080(无解) / 0.983 | 1.238(无解) / 1.156(无解) |
| 前 20000 | 11.1% / 48.9% | 1.179(无解) / 1.109(无解) | 1.337(无解) / 1.303(无解) |

来源：`[gap]` 当前覆盖率代入行 + `[gap-A-token]` 行。可见**只有前 1000 高频二字词、且按词频加权时，K=0.7 才勉强可达（需 p=82.3%，已高于外部研究的 74%）；K=0.6 在任何一个当前覆盖率口径下都需要 p≈97% 或更高，实际不可行。**

### ③.2 框架 A：锁定打词率 p，反解覆盖率 q

若打词率就取外部门槛 p=74%（K=0.7）/ p=87%（K=0.6），解 `q = 2 − 2·(K − (1−p)·c1)/p`：

| 目标 | 锁定 p | 所需二字词一击覆盖率 q |
| :--- | ---: | ---: |
| K = 0.7 | 74% | **≥ 99.98%** |
| K = 0.6 | 87% | **≥ 99.99%** |

来源：`[gap] 锁定p`。**这是本报告最关键的数字**：外部研究的 74%/87% 门槛建立在 `cw=1` 即「词全都能一击」的假设上；一旦承认有词需两击，覆盖率必须几乎 100% 才能维持原门槛。当前 71%/84.4% 差 16–28 个百分点。

覆盖率 q 与所需打词率 p 的权衡（`[gap]` 全表，p>1 即无解）：

| q | K=0.7 所需 p | K=0.6 所需 p |
| ---: | ---: | ---: |
| 100% | 74.0% | 87.0% |
| 95% | 76.5% | 89.9% |
| 90% | 79.1% | 93.0% |
| 80% | 85.1% | 100%（临界） |
| 70% | 91.9% | 无解（108.1%） |
| 60% | 100%（临界） | 无解 |
| 50% | 无解（109.6%） | 无解 |

推论：覆盖率低于 60% 时 K=0.7 无解、低于 80% 时 K=0.6 无解——再高的打词率也救不回来。

### ③.3 框架 B：打词率受覆盖率约束（p ≤ q）

更自洽的口径：用户只会打能一击的词，故 p 不可能超过覆盖率 q，取 p=q。此时
`K = (1−q)·c1 + q·(2−q)/2`，令 `0.5q² + (c1−1)q + (K−c1) = 0`，正根即临界覆盖率：

| 目标 | 临界覆盖率 q | 对应打词率 p=q |
| :--- | ---: | ---: |
| K = 0.7 | **≥ 83.1%** | 83.1%（已高于外部 74% 门槛） |
| K = 0.6 | **≥ 91.9%** | 91.9%（已高于外部 87% 门槛） |

来源：`[gap-B]`，q=0.8312→K=0.700、q=0.9186→K=0.600（解析解验算）。
对照现状：前 1000 二字词按词频加权 84.4% 刚好越过 K=0.7 线（K=0.686），但 K=0.6 仍差 7.5 pp；前 5000（61.9%）连 K=0.7 都不到。**这给出了票 02 的直接回答：要让二字词一击覆盖率「自洽支撑」目标，覆盖率至少要到 83%（K=0.7）/ 92%（K=0.6）；若坚持外部研究的低打词率门槛，则要到 ~100%。**

### ③.4 硬前提校验：词均码元数 ≤2

二字词平均最短码元数前 1000 / 5000 / 2 万 = **2.58 / 3.34 / 3.77**（`[mass]`）。外部研究指出一旦词均码元数 m≥3，`cw=⌈m/2⌉` 就变 2，即使打词率 100% 也到不了 0.6–0.7。当前前 5000 起的二字词均已达 3.34，说明**缺口是结构性的**：不是覆盖率小数点后的 adjustment，而是绝大多数高频二字词（前 2 万中 88.9%）本就是 3–4 码元、需两击。

## ④ 零和冲突面

口径：一击上屏码 = 可达（在 9111 个一次并击可达码内）且零延伸且唯一候选，共 **1377** 个（单字 529 / 词 781 / 其他符号 67）；此数与 `char_onehit_report.md` §6 的 1377 完全一致，验证脚本口径正确。（`jianma_reference.md` 的 1396 是「码元数≤3 且零延伸唯一」的更宽口径，含 19 个 chord 判不可达的死码，本票统一用 chord 口径 1377。）

前 1500 常用字占其中 455 个单字槽（30.3%），另有 74 个单字槽在榜单外。每个一击码只有一个首选槽，给词就必然挤掉字/词——这是硬零和。

**每 100 个槽从单字转给词的冲突面**（S_char=529，100 槽 = 18.9% 的单字一击地盘）：

| 让位策略 | 假设 | 前 1500 字一击率 | 跌幅 |
| :--- | :--- | ---: | ---: |
| A 均匀让位 | 从 529 槽按比例均匀抽走 | 30.3% → 24.6% | **−5.7 pp** |
| B 优先低频 | 先用榜单外 74 槽，再伤 26 个榜单内字 | 30.3% → 28.6% | **−1.7 pp** |
| C 最坏（全高频） | 100 槽全来自榜单内字 | 30.3% → 23.7% | **−6.7 pp** |

来源：脚本 `[slots]` / `[zero-sum]` 行。

解读：
- **乐观情形（B）**：把符号族/榜单外低频单字槽（74 个）先让给词，几乎不伤常用字一击率（仅 −1.7 pp）。但 74 个槽对「二字词覆盖率从 71% 提到 83%+」只是杯水车薪——前 1000 就有 221 个二字词未一击，缺口远超可用闲槽。
- **现实情形（A/C）**：一旦动到高频字槽，每 100 槽要付 5.7–6.7 pp 的单字一击率代价。而单字一击率 c1 正是 K 模型的另一半：c1 每降，p 门槛还要上抬（52dazi 报告 §4.4 已量化：c1 从 1.269 降到 1.0 可省约 13 pp 打词率）。即「拆东墙补西墙」在 K 上往往净亏。
- **净和估算**：把 100 槽给词，按词频质量可让前 1000 二字词覆盖率 +13 pp（84.4%→~97%），q 收益反映为 cw 从 1.156 降到 ~1.03；但单字一击率若按 A 掉 5.7 pp，c1 约升 0.06。二者代入 K 模型，在 p≈0.8 时净效应接近相抵——说明零和约束下靠内部重排很难突破 0.6。

4. **过滤口径**：纯 CJK（`\u4e00`–`\u9fff`）词条，排除标点/数字/含 `〇` 等（覆盖全表 99.97% 词频）；单字、二字词、多字词分列，二字词单列。
5. **运行命令**：`/home/jackwy/.workbuddy/binaries/python/versions/3.13.12/bin/python3 .scratch/km-code-length-0.6/research/word_coverage_analysis.py`（原样重跑即可复现全部表格）。
6. **只读保证**：脚本仅 `open(..., encoding='utf-8')` 读词库/词频，未写任何现有文件；本报告与 `word_coverage_analysis.py` 为新增文件。

### 未确认项 / 边界
- **语料时效性**：`essay.txt` 是 Rime 官方打包语料，其采集年代与题材分布**未确认**；作为高频词表可复现，但未必代表当下网络/专业领域打词分布。替代方案：换任一分词+词频表（如人民日报语料、百度/清华中文词频表）重跑脚本第 1 步即可，脚本其余逻辑不变。
- **词频「词」口径**：essay 的分词粒度与空明码实际打词习惯（用户可能把「我们」当一个词、也可能拆开）存在差异；p 的实测值目前无空明码用户数据可验证（52dazi 报告 §⑤-1/2 亦记为未确认）。
- **p=q 是理想假设**：框架 B 假定用户只打能一击的词；现实中打词率还受肌肉记忆、选重、候选位置影响，p 未必等于 q，故 83%/92% 是「自洽下界」而非实测门槛。
- **零和模型简化**：§④ 把「转 100 槽」映射为按词频比例损失单字一击，未建模重排后用户可改用「一击+空格」或两击兜底；实际跌幅可能略小于估计。被挤掉的字/词不会被删除，仍可用全码输入。
- **c1=1.269 / L=2 沿用外部估算**：这两个参数是 52dazi 报告 §4 的「我的估算」，非实测；若 c1 更低（单字一击率更高）或 L 更长（长词为主），门槛 p/q 会相应下降，但「词均码元数 ≤2」的硬前提不变。
- **一击口径差异**：本报告用 chord 口径 1377；`jianma_reference.md` 用码元数口径 1396，差 19 个死码，已在 §④ 标注，未混用。
