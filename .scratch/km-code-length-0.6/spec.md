# Spec — 把空明码平均码长从 0.8 降到 0.6–0.7

Status: ready-for-agent
Effort: km-code-length-0.6
Source: wayfinder 地图 `.scratch/km-code-length-0.6/map.md` + 票 01–05 + 用户 2026-11-16 拍板
Created: 2026-11-16

## Problem Statement

空明码（双手并击、大词库中文输入方案）当前平均码长为 **0.8 击/字**（一次并击 = 双手各按一个码元 = 1 击）。用户希望降到 **0.6–0.7 击/字**，以降低打字时长与疲劳。

降码长受三个杠杆约束，且优先级已探明：

- **单字一击率**（`c1`）：前 1500 常用字 73.1% 可一次并击出，`c1=1.269`，已接近物理上限，空间很小。
- **打词率**（`p`）：由用户打字习惯决定，输入法无法直接控制。
- **二字词一击覆盖率**（`q`）：前 1000 高频二字词仅 71%（词数）/ 84.4%（词频加权），前 5000 降到 32.9% / 61.9%，**这是输入法侧最大且可改的杠杆**。

核心困难：现有 1377 个一击上屏码中单字与词零和争抢（给词就挤字）；且二字词平均编码 2.58–3.77 码元，多数本就需两击。此前所有优化都在存量槽里腾挪，收益见顶。

## Solution

用户视角的解决方案分三层，按「先拿稳、再冲刺、配套验收」推进：

1. **先把验收尺子定死**：区分理论码长（按码表算的最小击数）与实测码长（真实打字统计），两条独立达标线；严格计击（预测上屏、空格确认均计一击）；打词率与选重率作配套约束，防止账面虚低。
2. **增量扩容（拿 0.7 的主力）**：利用词库未占用的 **5086 个干净一击空槽**（符号前缀族 `< ; ! @ ?` 等各 90–98 个、双符号码、大写+符号族），优先把高频二字词挂成一击上屏，把覆盖率推过 K=0.7 门槛（自洽口径需 ≥83.1%）。这一步不挤占现有单字槽、不改打字习惯。
3. **冲 0.6 的配套（可选、代价大）**：0.6 需覆盖率 ≥91.9% 且词均码元数 ≤2，而现有高频二字词普遍 3–4 码元，须靠长词/短语简码 + 打词率训练 + 必要时改 algebra 底层规则。建议先完成第 2 步拿到 0.7 再评估是否投入。

## User Stories

1. 作为打字用户，我希望常用二字词能一次并击直接上屏，这样我不必打两击再按空格。
2. 作为打字用户，我希望插入新简码时不会截断我已习惯的长词输入。
3. 作为打字用户，我希望单字一击率不因为给词让槽而下降。
4. 作为打字用户，我希望数字大写输入（`X~` 族）保持原样，不被这次优化破坏。
5. 作为打字用户，我希望最终码长能被客观测量，而不是凭感觉说「变快了」。
6. 作为打字用户，我希望理论码长与实测码长分开报告，避免用理论值冒充实际体验。
7. 作为打字用户，我希望统计码长时把选词、空格确认、预测上屏都算作一击，得到诚实的数字。
8. 作为打字用户，我希望同时看到打词率与选重率，防止靠极端打法凑出低码长。
9. 作为维护者，我希望有一份可复现的语料与脚本来算理论码长，每次改动前后可对比。
10. 作为维护者，我希望新增简码前能预览会占用哪些空槽、挂哪些词，确认后再写库。
11. 作为维护者，我希望写库默认只预览，显式确认才落盘，防止误操作污染词库。
12. 作为维护者，我希望每次写库自动生成备份，出问题能一键回滚。
13. 作为维护者，我希望简繁两套词库同步更新，避免繁体用户得不到同样的短码。
14. 作为维护者，我希望每个待挂词都先校验目标码「词库未占用、且不是任何现有码的前缀」，杜绝伪空槽。
15. 作为维护者，我希望零延伸槽只置换不追加（一个码挂两个词会退化成必须空格选词，反而更慢）。
16. 作为维护者，我希望复用现有的击数权威模型判定可达性，不靠肉眼数码元。
17. 作为维护者，我希望符号族既有的语义分工（叠字/二字/三字/数字大写）不被新挂词打乱。
18. 作为维护者，我希望改动能部署到当前输入法后端并复核生效。
19. 作为维护者，我希望全量版 `kongmingma`（300 万）是否同步能单独决策，不默认卷入。
20. 作为审阅者，我希望规格里的每个关键数字都标注来源（脚本/报告），可追溯核验。

## Implementation Decisions

- **击数口径**：以 `km_chord_model` 为唯一权威；一次并击 = 左右手各一码元 = 1 击；击数 = ⌈码元数/2⌉。符号 `< ; ! @ ?` 均为可达前缀，`'` 是右手单键并击，`/` 可达；`X~` 数字大写族永不外借；含 1–6 的码不可用（只能 Ctrl 送键，比全码慢）。
- **先增量、后存量**：新增简码一律优先投放到 5086 个干净空槽（可达 + 词库未占用 + 非任何码前缀），不挪用现有 1377 个一击码中的单字槽；守住 `c1=1.269` 不恶化。存量零和重排（拆单字给词）在本轮不做。
- **五符号族现状**：`< ; ! @ ?` 每族约 134 个可达码，已占用 32–39 个（多为高频词与叠字族），真正干净空槽各 90–98 个；挂词前须逐槽校验，`@k` 这类「是其他码前缀」的伪空槽必须排除。
- **工具链分工**：新增「词→空槽」批量分配脚本（现有工具只覆盖按词频提码到既有槽位、符号族/数字族改派，缺批量映射到全新空槽的能力）；复用 `km_jianma_zero.py`（零延伸符号族，只置换不追加）、`km_jianma_digit.py --set`（单槽改派）、`km_chord_model`（可达性与击数判定）。默认预览、`--apply` 才写库、`--with-trad` 同步繁体、写前自动备份。
- **验收脚本（新增）**：一个 aggregate 指标工具，输出四数——理论码长 / 实测码长 / 打词率 / 选重率。理论码长按跟打器「理想码长」口径（按码表算每个字词的最短击数，打词率从固定高频词表推算，可复现）；实测码长按用户日常随机文本统计。达标线：理论 ≤0.7、实测 ≤0.8，两条独立判定。
- **词库排序约束**：词库为严格两列 `词条<TAB>码`、`sort: original`，同码候选按文件行序排、无权重列。故「提码」的实质是决定某词条的去留而非调权重；删除某码位唯一真候选会让「字+空格+后缀」构造顶到首位，须护栏跳过或按备份回补。
- **同步范围**：本轮只动 `kongmingmas` 简繁镜像；全量版 `kongmingma`（300 万，简码仍是旧的）是否纳入单独决策，默认不动。

## Testing Decisions

**好测试的标准**：只测外部可观察行为（输入的词能否一击上屏、码长指标是否正确、写库是否安全），不测内部实现细节；可复现、可对比改动前后。

**候选 seam（已存在，优先复用）**：
- 词库文件本身（`kongmingmas.dict.yaml` 两列结构）：软 seam，用只读脚本解析比对。
- `km_chord_model` 的击数判定：硬 seam，作为可达性/击数的唯一判据直接调用。
- 写库 CLI 的「预览 / `--apply` / `--with-trad`」行为：硬 seam，用预览模式断言不改盘、`--apply` 才落盘并备份。

**拟新增 seam（仅一处，放在最高点）**：验收指标工具作为聚合入口——输入一段文本 + 词库，输出理论/实测码长与打词率/选重率。所有端到端断言走它，避免在多个模块里重复实现口径。

**具体测试**：
- 可达性测试：五符号族的干净空槽样例逐一断言「在 one_press_codes 内、词库无此码、非任何码前缀」；伪空槽（如 `@k`）断言被排除。
- 唯一候选测试：每个新增一击码断言零延伸且唯一候选，防止退化成需空格选词。
- 回归测试：现有高频词的一击上屏结果、单字一击率、`X~` 数字大写族、叠字族语义在改动前后不变。
- 指标测试：用固定样本文本断言理论码长计算可复现、数值落在预期区间；断言严格计击下预测/确认动作被计入。

## Out of Scope

- 52dazi 榜单冲榜与账号运营（该站只作外部校准数据）。
- 拼音/五笔等非并击方案的码长优化。
- 结构性重构 algebra / 改并击维度冲 0.6（本轮先拿 0.7，0.6 作为 stretch goal 另案）。
- 引入 Lua 预测 / 联想 / 改引擎 predictor（破坏「纯原生零 Lua」，且严格计击口径下对码长无净贡献）。
- 引导用户改变打字习惯的具体训练法（属 dazitui 项目，本 spec 只产出对打词率的指标要求）。
- 全量版 `kongmingma`（300 万）词库的简码同步。

## Further Notes

- **目标现实性**：自洽口径下 K=0.7 需二字词一击覆盖率 ≥83.1%（当前前 1000 词频加权 84.4% 已临界达标），K=0.6 需 ≥91.9% 且词均码元数 ≤2（当前前 5000 为 61.9%、3.34 码元，结构性不达标）。故 0.7 可达、0.6 需底层重构。
- **关键区分**：票 01 的 5086 空槽是「增量」（符号前缀族/双符号/大写+符号，挂词不挤现有），票 02 的零和是「存量 1377 槽内」单字与词争抢——二者分层成立，不矛盾。
- **证据索引**：`docs/reports/52dazi_code_length_research.md`（口径与模型）、`.scratch/km-code-length-0.6/research/one-strike-capacity.md`（容量）、`word-coverage-gap.md`（覆盖率缺口）、`mechanism-feasibility.md`（机制可行性）、票 04（验收协议）、票 05（槽位取舍）。
- **已验证脚本**：`research/check_symbol_slots.py`（五符号族实测）、`research/verify_slot_count.py`（计数去重核实），只读、未改词库。
